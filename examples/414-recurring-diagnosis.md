# 示例一：414 偶发报警的复发诊断

> 基于本地端到端实测整理，文字有节选；设备/工单/案例均来自仓库附带的**虚构演示种子**。
> 场景目的：验证「安全前置 + 跨表检索 + 复发命中」。

## 场景

设备 **CNC-01**（台账：CK6140，沈阳机床，FANUC 0i-TF，液压卡盘/尾座）加工中偶发 X 轴 414 报警，
复位有时可恢复，**晃动拖链电缆更易复现**，且上个月因类似问题停过。

## 用户提问（要点）

> CNC-01 今天又跳 X 轴 414，晃拖链更容易复现，上个月好像也犯过。先查设备档案、414 含义和历史工单/故障案例，判断最可能原因和处理办法。

## 助手动作（按调用顺序）

1. 加载 `fault-triage`、`alarm-decode` 技能；
2. 通过 MCP 只读查询：
   - `machines WHERE machine_code='CNC-01'` → 确认机型 / 系统 / 液压配置；
   - `alarms WHERE alarm_code='414'` → FANUC 0i「第 n 轴数字伺服系统报警」，提示看诊断位 DGN 200/204；
   - `work_orders WHERE machine_code='CNC-01' ORDER BY created_at DESC` → 命中在途工单 **WO-20260920-04**：
     “X 轴偶发 414，摆动拖链可复现”，状态 `diagnosing`，已申领高柔性编码器线缆、**待停电更换**，`loto_required=1`；
   - `fault_cases` → 命中**复发案例 #4**：
     “X 轴编码器线缆随拖链长期弯折导致内部芯线疲劳虚接（**复发故障**）”。

## 结论节选

- 报警指向 **X 轴伺服编码器/反馈回路**；结合“晃动拖链可复现”，最高概率根因为
  **拖链段编码器电缆内部断芯/虚接、插头松动或屏蔽/接地不良**，编码器本体损坏概率低。
- 明确点出这是**复发且上次未闭环**：已确诊、已申领线缆，但因未安排停机窗口未更换。
- **安全前置**：涉及伺服电缆/电机接线，必须先停机断电、LOTO 上锁挂牌，等待驱动器电容余电释放、指示灯熄灭，
  **严禁带电插拔或动车缆**；测线需电气维修工对照机型手册针脚定义进行。
- 处置建议：定位破损点 → 检查两端插头与屏蔽接地 → 伺服编码器电缆**不建议现场接续，整根更换同型号** →
  换后空载走全行程 + 试切、确认 DGN 200/204 清零、连续运行半天观察。
- 收尾：建议把 WO-20260920-04 更新为“已修复 + 根因 + 更换件 + 验证结果”并关联案例 #4；
  若安排停机上锁换线，可继续生成 LOTO 能量隔离作业票（见示例二）。

## 验证点

- 多次 `machine-db_*` 只读调用全部成功（含中文结果），无 skill policy 拦截、无超时；
- 答案严格落在“分析 + 建议”，把是否停机/拆修的**决策**留给现场负责人；
- 对查得到的报警码引用本地库与手册诊断号，未做超范围编造。
