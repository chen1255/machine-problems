# 报警码解读技能（alarm-decode）

把一个报警码转成**含义、风险等级、处置步骤、复位条件**都清楚的现场答复。
同一个报警码在不同数控系统、不同机床厂自定义报警里含义可能完全不同，因此**系统品牌是第一输入**。

## 触发逻辑

- **触发方式**：用户提供报警号/报警文本，想知道含义、影响和怎么处理。
- **触发示例**：
  - "FANUC 0i 报 414，X 轴伺服报警"
  - "屏幕显示 1006 DOOR INTERLOCK，门都关好了还消不掉"
  - "西门子 25000 编码器硬件故障怎么办"
- **不触发**：报警只是故障的一个表现、需要整套排查 → `fault-triage`。

## 报警类别先分清（决定查哪里）

| 类别（以 FANUC 为例） | 典型号段 | 含义来源 |
|---|---|---|
| P/S 程序报警 | 000–255（如 070/071/100） | 系统统一定义 |
| 伺服/编码器报警 | 3xx、4xx（如 414/436/438/439） | 系统定义，细节看诊断画面（如诊断号 200/204） |
| 系统/过热报警 | 700/701、9xx 等 | 系统定义 |
| 机床厂自定义（PMC/PLC） | **1000 起（1000–1999、2000+）** | **机床制造商编写，各厂不同，必须查该机床手册/梯图** |
| SIEMENS | 如 25000/25080/3000 等 | 西门子体系，不与 FANUC 互通 |

关键提醒：**FANUC 1000 以上的号是机床厂自定义文本**，联网搜到的同号结果可能来自别的机床、含义不同，不能直接套用。

## 工作流程（严格按序）

1. **确认系统身份**：品牌 + 系列（FANUC 0i-MF/TF、31i；SIEMENS 828D/840D sl；三菱 M70/M80；广数/华中…）。缺失就先问这一个问题，不要凭号码猜。
2. **本地库精确查**：用 machine-db 对 `alarms` 表按"报警码 + 系统"匹配（必要时模糊匹配同系列）。命中则进入第 4 步。
3. **未命中不编造**，按下列顺序：
   - 若为 1000+ 自定义报警：明确告知"这是机床厂自定义报警"，引导查本机床《操作说明书/维修说明书 报警清单》或 PMC 报警文本页，并建议记录屏幕完整英文文本。
   - 系统标准报警：可用 WebSearch 以"品牌 系列 报警码 + 报警文本"检索，优先官方手册/权威来源，并在答复中标注来源与"以本机床手册为准"。
   - 仍不确定：如实说明，建议联系设备厂家/售后并提供系统型号与完整报警文本。
4. **给结构化解读**：含义 → 触发条件/常见原因 → 风险等级 → 处理步骤（含安全前提）→ 复位条件与复位后验证。
5. **安全联动**：伺服、编码器、超程、过热类报警的处置可能涉及带电检测或机械运动；先给安全提醒；属高危处置的步骤按 SOUL 要求委托 safety-reviewer 复核。
6. **知识沉淀（用户确认后）**：把核实过、手册可查的报警码（含义/原因/处置/等级/手册章节）补录进 machine-db `alarms`，标明系统与来源，逐步形成本厂自己的报警字典。不确定来源的不入库。

## 输出格式

使用 `templates/alarm_template.md`。要点：

- 顶部固定一行"系统 + 报警码 + 一句话含义 + 风险等级（信息/警告/严重/危险）"。
- 复位方法要区分：**软复位（RESET）即可 / 需排除原因后复位 / 需重新回零 / 需断电重启 / 需厂家参数**。
- 凡引用库外来源，标注链接或"据 XX 手册"，并保留"以本机床实际手册为准"。

## 禁止事项

- 禁止在不确认系统品牌时给报警码下结论。
- 禁止编造报警码含义、诊断号内容或复位操作；库中无、来源不可信就直说。
- 禁止把 A 机床厂 1000+ 自定义报警文本套到 B 机床。
- 禁止省略伺服/高压/运动相关报警处置前的安全提醒。
- 禁止指导用户通过改参数、屏蔽限位/门锁联锁等方式"绕过"报警让机器强行运行。
